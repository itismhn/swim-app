# Key user journeys

1. **Coach takes attendance at the pool (phone).** Dashboard → "today" card → *ثبت حضور* → tap a status for each swimmer (big buttons), *✓ بقیه حاضر* fills the rest → *ذخیره*. Each change writes an `AttendanceHistory` row (who, when, from → to, note); edits to an existing record also go to the audit log. Cancelled sessions refuse attendance and never count in rates.
2. **Coach builds and publishes a pool workout.** *تمرین در آب* → *برنامه جدید* → pick group or individual athlete, date, pool length → edit the six sections; per set: rounds × reps × segments (e.g. 20 m fast + 5 m easy), stroke, intensity, rest, send-off, equipment, focus, notes. Volume updates live; a warning appears if a rep doesn't end at a wall. *ذخیره پیش‌نویس* or *ذخیره و انتشار*. The server recomputes planned volume, stores a revision, and notifies athletes and verified guardians on publish.
3. **Athlete reports a workout.** Notification → plan → *گزارش اجرای تمرین*: actual metres (stored apart from planned), RPE 1–10, feedback → coaches are notified and can reply on the plan page.
4. **Athlete logs dryland and flags pain.** *تمرین خشکی* → plan → per exercise: done, difficulty, *درد یا ناراحتی داشتم* + note → coaches, head coaches and verified guardians receive a ⚠ notification; the coach dashboard lists recent pain flags. No diagnosis or treatment is offered.
5. **Guardian gains access.** Guardian account → *فرزندان من* → name + Jalali birth date + relation → request is stored as PENDING (the response is identical whether or not a match exists) → admin/head coach verifies at `/app/admin/guardians` → only then can the guardian see the athlete.
6. **Nutrition consultation.** Athlete/guardian → *تغذیه* → request (allergies only with guardian consent; minors cannot enter them themselves) → admin assigns a nutritionist → nutritionist (who sees only assigned requests) replies; the reply is labelled as individual professional advice, separate from general education articles.
7. **Recording a time and a new PB.** Coach → *رکوردها* → athlete, stroke, distance, course, time `1:02.35`, type (official / practice), splits → if it beats every *comparable* result (same stroke + distance + course) the athlete and guardians get a "new PB" notification; the chart shows it (stars = official, circles = practice; reversed axis "lower is better"; baseline & season target lines).
8. **Registration → onboarding.** Visitor submits `/register` → admin sees it on the dashboard / `/app/admin/inquiries` → contacts the family → creates the athlete (`/app/athletes/new`) and guardian account (`/app/admin/users`) → links and verifies them.
